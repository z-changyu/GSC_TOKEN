## 1. 项目目标与实验设定

### 1.1 研究问题

在时变信道下做**生成式语义通信**：发送端 VLM 把图像+问题压成一段语义报告，逐 token 做语用重要性打分（A/S/G 三分量），在**可靠容量预算**约束下选择 token 并分配差异化保护等级（r_H/r_M/r_L = 48/32/16 等效比特），使接收端 LLM 的问答准确率最大。

### 1.2 与论文原设定的偏离（已确认，按实测写论文）

| 项 | 论文原文 | 本项目实测 |
|---|---|---|
| 数据集 | ScienceQA 5000 含图样本 + 五折 | **V2X-QA** test 150 样本（后续切回 ScienceQA 时为 300 含图 + 五折） |
| 发送端 | BLIP-2 | **Qwen3-VL-8B-Instruct**（BLIP-2 的 Q-Former 是双向注意力，不满足 II-C 因果假设） |
| 接收端 | Flan-T5-Large | **Qwen3-4B** |
| 语义相似度 | CLIP ViT-L/14 | ❌ 未接入（`src/metrics/semantic.py` 为空壳） |
| prompt 长度 | N ≤ 64 | 实测均值 132.9、p90 192、max 192 |
| 信道 | 4 种（含 DeepMIMO I1） | 3 种合成衰落 + ideal（**DeepMIMO 无本地数据**） |
| 权重 λ | (0.25, 0.30, 0.45) | 沿用该值（校准尝试失败，见 §6.2） |

### 1.3 关键无线参数

`B = 1 MHz`、`T_s = 1 ms` → 1000 信道使用/时隙；`ε_out = 0.05`；`σ_e² = 0.01`；丢包率 0.05；
码本 `ρ = (1/3, 1/2, 1)`（由 `b_tok = 16` 等效信息比特/token 推出）；`β = 0.25`；`T_max = 8`。

**可靠容量校准（最干净的结果）**：

#### 实验 3：语义代理验证

- 单 token 一阶：代理尺度标定 **α = 0.917**；70% 的 token 删除后 NLL 上升；但秩相关仅 **Spearman 0.22**（排序较噪）
- 集合级：真实 NLL 增量远小于 `Σ u'_i`（尺度比 ≈ 0.17），`G_i` 是 L2 范数乘积（恒非负、方向盲）→ **系统性高估**
- 结论：式 (27) 只能在**单 token 一阶**层面陈述，不可声称集合级余项紧界（覆盖率仅 0.45）

#### 实验 5：多终端精度–公平性前沿（K ∈ {4,10,20}）

| SNR | K | θ→0（bang-bang） | θ≈0.1–0.5（峰） | θ→∞（等 split） |
|---|---|---|---|---|
| 15 | 4 | 0.133 / jain 0.25 | **0.550** / jain 1.0 | 0.500 / jain 1.0 |
| 15 | 10 | 0.033 | **0.383** | 0.333 |
| 15 | 20 | 0.017 | **0.283** | 0.233 |

→ 验证式 (62) 的 Pareto 前沿：bang-bang 既不公平、精度也差；**中等 θ 同时取得最高精度与高公平性**，且最优点随 K 增大向更小 θ 移动。

#### 实验 6：复杂度与消融（Rayleigh + Rician + Freq-sel 三信道）

## 5. 已知问题与"坑"（交接重点）

### 5.1 GPU / 环境

- **8B 接收端在 24 GB 单卡 OOM**。加载器已加 `receiver_load_in_8bit` 支持，并修复了回退时显存未释放的 bug。跑 8B 接收端必须开启 8bit。
- **曾发生驱动级联崩溃**：8B 接收端 OOM 拖垮 GPU1 后，CUDA 驱动整体失效（两卡均 `Unable to determine the device handle: Unknown Error`，`CUDA initialization failed`）。**已由用户于 2026-08-31 修复**。若再发，需重启/重置驱动，`torch.cuda` 任何调用都会报 `invalid argument`。
- **配置强制覆盖 GPU**：`configs/experiments/*.yaml` 的 `experiment.cuda_visible_devices` 会在脚本内覆盖外部 `CUDA_VISIBLE_DEVICES` 环境变量。想换卡必须改配置（已有 `v2x_edge_edge_8b_calib.yaml` 指向 `"1"` 先例），直接 `export` 无效。
- **下载模型需先 `unset http_proxy https_proxy`**（本机代理 127.0.0.1:7890 未运行，hf-mirror.com 可直连）。
- `hfd.sh` 在 >2 GB 仓库有 bash 算术 bug（awk 科学计数法），**不影响 aria2c 本体下载**，忽略即可。

### 5.2 方法学陷阱（务必转达）

- **方法间共享 `rng`**：`run_channel_experiment.py` 中 `rng = random.Random(seed*1000003+position)` 在 `for method` **循环外**创建，随机化 LP 取整/局部精炼的抽取在各方法间连续推进。后果——proposed 与 plugin_capacity（同一调度器 + 同一预算）**并非逐元素相等**，残差 ±2–5pp（n=180 时 CI95 ≈ ±7pp，属噪声）。**论文不能声称 proposed 严格优于 oracle**，只能说统计并列。若要严格并列，需做 P3-13 的 CRN 修复。
- **改预算会改变 rng 消耗轨迹**，进而轻微改变后续所有方法的结果。因此 `channel_8b/`（保守）与 `channel_8b_maxbudget/`（max）的基线列也**不是同一条随机轨迹**，对比时留意。

### 5.4 论文表述红线（已确认的诚实性约束）

1. **式 (27) 的余项界不可声称集合级紧界**（覆盖率 0.45），只能在单 token 一阶（α≈0.92）层面陈述，并说明代理是方向盲的保守上界。
2. **A/S/G"三维融合"的贡献声明应降调**：消融显示 G_i 主导（移除即崩溃到 0.018），A/S/耦合在 G 之上增益很小。
3. **0 dB / 多终端 0 dB 等低于随机猜测的区**，必须同时报告预算/TRR 并定性为"可行性边界"，不能只报低精度。
4. **proposed(max) 与 oracle 只能说统计并列**，不能说超越——二者是同一调度器 + 同一预算。
5. **Rician 中断率 0.065 略高于目标 0.05**（CI ±0.036 含 0.05），需如实写实测值与置信区间。

| 模型组合 | Qwen3-VL-8B（发）+ Qwen3-4B（收）；BLIP-2 + Flan-T5 不复用 |
| 论文口径 | **按实测写**：prompt 长度、样本规模、结果论断一律以实测值为准，第六节重写 |
| 硬件 | 单卡 `CUDA_VISIBLE_DEVICES=0`（换卡需改配置，见 §5.1） |
| 权重 | **沿用 legacy (0.25, 0.30, 0.45)**；校准尝试失败（§5.3） |
| proposed 预算 | `configs/experiments/v2x_edge_edge_8b.yaml` 中 `proposed_budget: "max"`（`max` = Genie 容量 = 与 oracle 同预算；`conservative` = 式 (6) `c_eps`，默认行为） |

### 6.2 权重校准：负面结果（勿重复踩坑）

2026-08-30 用独立验证集做 λ 交叉验证，得到 (0.10, 0.20, 0.70)，结论是"梯度权重越大越好"。但用该权重跑的 `channel_8b_v2` 显示 proposed 与 fixed_H 持平甚至更差，且该 run 用的是未过滤清单（不可比）。**结论：校准未带来可验证收益，保留 legacy 权重。** 若日后重做校准，务必：① 固定用同一个过滤清单；② 验证集与测试集不重叠；③ 直接以接收端精度为客观量（**不要用发射端 NLL**——`L_T` 带图像条件，剪 prompt 后 NLL 几乎不涨，目标面退化为噪声，会把 λ_A 标定成 0 并摧毁方法，见 §6.3）。

### 6.3 标定客观量的选择决定一切（重要发现）

同一批缓存打分、同一套 λ 网格，换标定客观量结论完全反转：

| 方法 | TRR 0.3 | TRR 0.5 | TRR 0.7 |
|---|---|---|---|
| legacy (0.25,0.30,0.45) | 0.400 | 0.473 | 0.527 |
| 折内**发射端 NLL** 标定 | 0.098 | 0.323 | 0.449 |
| 折内**接收端精度**标定 | **0.430** | **0.540** | **0.573** |

→ 论文必须写明 λ 是以**接收端任务精度**为目标网格搜索的，并说明为何不能直接用 `L_T`。

# 边缘-边缘收发端落地清单（方案 A：文本化多车协调接收端）

> 配套文档：`docs/场景重构与端到端数据流.md`。
> 目标态：发送端（车端边缘，VLM 看图生文）+ 接收端（边缘 RSU，纯文本协调 LLM 做 R1 摄入 / R2 跨视角融合 / R3 回答）。
> 本清单给出**模型选型、算力预算估算、获取方式、运行流程**，所有改动均已落到仓库（`src/data/v2xqa.py`、`scripts/fetch_v2xqa.py`、`scripts/run_v2x_co_fusion.py`、`configs/experiments/v2x_edge_edge.yaml`）。

---

## 1. 核心结论：为什么接收端可以（也应该）比发送端"大一点"

比较维度不是"谁盒子大"，而是**每参数的计算成本**：

| | 发送端（车端边缘） | 接收端（边缘 RSU） |
|---|---|---|
| 模型 | VLM（视觉塔 + LLM） | 纯文本 LLM |
| 固定开销 | **视觉编码是重头**，必须跑 | 无视觉塔 |
| 同边缘预算下 | `Qwen3-VL-2B` ≈ 2B LLM + 视觉塔 | 可塞下更大的纯文本 LLM |

发送端被迫背着视觉编码器这个固定成本，接收端没有，因此在**相同边缘算力/功耗预算**下接收端可承载更多 LLM 参数（如 `Qwen3-4B` 文本 LLM 实际运行时延/功耗可与发送端 2B-VLM 持平甚至更低）。所以"接收端比发送端 LLM 部分大一点"是合理的，且由工作负载差异自然推出，而非靠硬件优势。

## 2. 选型表（edge-to-edge）

| 角色 | 推荐模型 | 本地是否已就位 | 说明 |
|---|---|---|---|
| 发送端（车端语义发射端） | `Qwen3-VL-2B-Instruct` | ✅ `models/Qwen3-VL-2B-Instruct` | 视觉理解 + 报告生成；支持多图，CO 双视角可单前向吃下 |
| 接收端（边缘 RSU 文本协调器） | `Qwen3-4B`（纯文本） | ❌ 需拉取 | 比发送端 LLM 部分大；无视觉塔，同预算可扛；利好 R2 多路残缺报告融合 |
| 接收端降级（仅 1.7B 在本地时） | `Qwen3-1.7B` | ✅ `models/Qwen3-1.7B` | 把 `v2x_edge_edge.yaml` 的 `receiver_path` 改回 `models/Qwen3-1.7B` 即可 |

**两条硬约束：**
1. 接收端保持**纯文本**（方案 A 的命门）——不为"看图"换 VLM，否则削弱"只传文字、不传图"主线。要回应审稿人可另设"接收端也看图"的**独立上界实验**。
2. 收发端都用 **Qwen3 同族 tokenizer**：V3 逐 token 打分 ↔ R1 摄入对齐，R2 跨视角/跨车 token 空间一致，便于拼接。避免收发端跨 tokenizer 族。

## 3. 每端算力预算估算（BF16 / eager，单卡边缘可比参照）

| 项 | 发送端 Qwen3-VL-2B | 接收端 Qwen3-4B（文本） |
|---|---|---|
| 参数 | ~2.6B（视觉塔 ~0.6B + 2B LLM） | ~4B（纯 LLM） |
| 权重显存 | ~5.2 GB | ~8 GB |
| 每样本固定开销 | 视觉编码（~196 visual tokens， tens of ms）+ 生成 192-token 报告 | 无视觉开销 |
| 每样本生成量 | 192 token（语义报告） | 24 token（答案） |
| 相对算力 | 视觉塔 + 长生成 | 仅短生成，但每 token 2× 算力 |
| 结论 | 运行时更"重"（视觉塔固定成本） | 同预算可取更大参数，总算力持平或更低 |

> 若接收端是工业级边缘网关/服务器，可上更大文本 LLM；若接收端是车载同级边缘，**封顶 ~4B，不上 8B+**（无云端兜底，时延/功耗受限）。

## 4. 模型获取（接收端 Qwen3-4B 不在本地）

仓库自带 `hfd.sh`（多线程 / 可断点续传，默认走 `HF_ENDPOINT`）。**注意：当前开发机无外网**
（hf-mirror / huggingface / modelscope 均不可达），需在**有网的机器**执行下列命令，再把
`models/Qwen3-4B` 拷回本仓库：

```bash
export HF_ENDPOINT=https://hf-mirror.com
bash hfd.sh Qwen/Qwen3-4B --local-dir models/Qwen3-4B -x 8 -j 8
```

若仅做 smoke 验证，可把 `v2x_edge_edge.yaml` 的 `receiver_path` 改回本地已就位的
`models/Qwen3-1.7B`（纯文本，无需下载），其余参数不变。

发送端 `Qwen3-VL-2B-Instruct` 与降级 `Qwen3-1.7B` 已在 `models/` 就位，无需再下。

## 5. 运行流程（数据已就绪于 `datasets/V2X-QA`）

```bash
# 0) 环境
conda activate GSC_Token
export PYTHONPATH="$PWD"

# 1) 由本地克隆生成 processed + manifest（test 划分；可加 --tasks VS1 CO3 限定）
python scripts/fetch_v2xqa.py --split test --num-samples 150

# 2) 缓存语义报告（需 GPU + 发送端 VLM）
#    注意：run_cross_validation.py 是 ScienceQA 五折专用，不会为 V2X 建缓存；
#    V2X 用下面这个由 config 驱动的脚本（产出 SampleScores，供下游消费，支持断点续传）
python scripts/build_score_cache.py --config configs/experiments/v2x_edge_edge.yaml

# 2.5) 先跑 full prompt，只保留答对的样本进入后续实验（full 在保留集上即 100%）
python scripts/filter_by_full.py --config configs/experiments/v2x_edge_edge.yaml
#      -> data/manifests/v2xqa_test_filtered.jsonl

# 3) 信道实验：仅在过滤后的保留集上比较各压缩方法（full≈100% 作上界参考）
python scripts/run_channel_experiment.py --config configs/experiments/v2x_edge_edge.yaml \
    --manifest data/manifests/v2xqa_test_filtered.jsonl

#    或：run_pilot 直接对 processed 打分+评测（需把 manifest 指向过滤集）
python scripts/run_pilot.py --config configs/experiments/v2x_edge_edge.yaml \
    --manifest data/manifests/v2xqa_test_filtered.jsonl

# 4) R2 跨视角融合（CO 双视角 → 接收端融合作答，方案 A 关键缺口补强）
python scripts/run_v2x_co_fusion.py --config configs/experiments/v2x_edge_edge.yaml
```

- `fetch_v2xqa.py` 把 `datasets/V2X-QA/data/splits/{train,test}/<TASK>_annotations.jsonl`
  转成框架既有 `processed` schema（`row_idx / sample_id==str(row_idx) / image / question / choices / answer`），
  并把图像按 `image_id_vs` / `image_id_is` 解析到 `datasets/V2X-QA/data/raw_external/V2X-Seq-SPD-{vehicle,infrastructure}-side-image/`。
- VS → 车端图；IS → 路端图；CO → 主视图取车端图、路端图存于 `image_path_is` 供 R2 使用。

## 6. 当前环境限制（务必先修）

`README.md` 指明本机 **CUDA 不可用**（`nvidia-smi` 不可达、cu130 与 CUDA 12.2 不兼容），
模型实验目前被 gate 为 *blocked*；且**本机无外网**（hf-mirror / huggingface / modelscope 均
不可达），`Qwen3-4B` 需在有网环境拉取后拷回。上述是**设计态落地**；真要跑通需先修环境
（降级 PyTorch / 换驱动，或 CPU 仅跑 `Qwen3-1.7B` 做 smoke）。`run_pilot.py` 还会读
`outputs/model_capabilities.json` 的能力门，未 PASS 会直接退出。
